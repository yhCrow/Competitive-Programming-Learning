12.1 贪心与证明
Greedy	rules,	the	proofs	that	justify	them,	and	the	counterexamples	that	break	them.
IDEA A greedy algorithm builds the answer one step at a time, always taking the choice that looks best right
now, and never undoing it. It is short and fast, but only correct when you can prove that a locally best
choice never spoils the overall best answer.
KEY POINT Two standard proofs. Exchange	argument: take any optimal answer that differs from the greedy one,
swap one piece to match greedy, and show it gets no worse. Stays	ahead: after every step, greedy is at
least as good as any other method so far.

TRAP With coins 4, 3, 1, greedy pays 6 as 4 + 1 + 1 (three coins), but 3 + 3 needs only two. "Take the biggest
coin" is correct for some coin systems (1, 2, 5, 10 …) and wrong for others.
KEY POINT Before trusting a greedy rule, compare it with a slow brute force on many small random inputs (a stress
test). One mismatch kills the rule; no mismatches is evidence, and then look for the proof.
12.1.2 Sort	by	a	ratio:	partial	knapsack
partial_knapsack.cpp
1 #include <bits/stdc++.h>
2 using namespace std;
3  
4 struct Pile { int w, v; };
5  
6 int main() {
7     int n, cap;
8     cin >> n >> cap;
9     vector<Pile> p(n);
10     for (int i = 0; i < n; i++) cin >> p[i].w >> p[i].v;
11     sort(p.begin(), p.end(), [](const Pile &a, const Pile &b) {
12         return a.v * b.w > b.v * a.w;     // v/w larger first, no division
13     });
14     double total = 0;
15     for (int i = 0; i < n; i++) {
16         if (cap <= 0) break;
17         int take = min(cap, p[i].w);
18         total += 1.0 * p[i].v * take / p[i].w;  // a fraction of the pile
19         cap -= take;
20     }
21     cout << fixed << setprecision(2) << total << "\n";
22     return 0;
23 }

20 100
30 120
15 45
OUTPUT
240.00
IDEA Gold dust can be split, so value per unit weight is all that matters: take the richest pile first, then the next,
and cut the last one to fit (P2240).
KEY POINT Compare ratios v₁/w₁ > v₂/w₂ as v1 * w2 > v2 * w1 : exact in integers. When items cannot be split (0/1
knapsack), this greedy is wrong; that needs dynamic programming.
12.1.3 Exchange	argument:	shortest	job	first
order a b : a waits 0, b waits t_a
order b a : b waits 0, a waits t_b
everyone behind waits t_a + t_b either way,
so put the shorter one first: t_a < t_b

KEY POINT Swapping two neighbours changes only their own waits, so any order with a longer job before a shorter
one can be improved by a swap. Hence sorted by time is optimal (P1223). pair  sorts by the first field,
then the second; t[i].first  and t[i].second  read the two fields.

12.2 哈夫曼编码
Always	merge	the	two	smallest:	priority	queues	and	optimal	codes.
100
f 45 55
25 30
c 12 d 13 14 e 16
14 = a 5 + b 9 (one level lower)
IDEA Huffman	coding gives frequent characters
short codes and rare ones long codes. Build a
tree: repeatedly take the two	smallest
weights, join them under a new node whose
weight is their sum, and put it back. Each
character's code length is its depth.
KEY POINT The total cost (sum of frequency × code
length) equals the sum of all the joined
weights. Why greedy works: the two rarest
symbols can always be placed deepest, as
siblings, in some optimal tree.
merge_fruits.cpp
1 #include <bits/stdc++.h>
2 using namespace std;
3  
4 int main() {
5     int n;
6     cin >> n;
7     priority_queue<long long, vector<long long>, greater<long long>> pq;
8     for (int i = 0; i < n; i++) {
9         long long x;
10         cin >> x;
11         pq.push(x);                      // min-heap: top() is the smallest
12     }
13     long long cost = 0;
14     while (pq.size() > 1) {
15         long long a = pq.top(); pq.pop();
16         long long b = pq.top(); pq.pop();
17         cost += a + b;                   // merging costs the new heap's size
18         pq.push(a + b);
19     }
20     cout << cost << "\n";
21     return 0;
22 }

KEY POINT priority_queue  keeps the largest element on top; with greater<long long>  it keeps the smallest.
push  and pop  cost O(log n), so n merges cost O(n log n) (P1090: merging fruit heaps is exactly a
Huffman tree).
TRAP Sorting once is not enough: each merged heap must go back among the others, possibly in the middle. That
is why a priority queue is used.
huffman_lengths.cpp
1 #include <bits/stdc++.h>
2 using namespace std;
3  
4 int main() {
5     int n;
6     cin >> n;
7     vector<char> ch(n);
8     vector<long long> w;
9     vector<int> parent;                       // tree stored by node number
10     for (int i = 0; i < n; i++) {
11         long long f;
12         cin >> ch[i] >> f;
13         w.push_back(f);
14         parent.push_back(-1);
15     }
16     priority_queue<pair<long long, int>, vector<pair<long long, int>>, greater<>> pq;
17     for (int i = 0; i < n; i++) pq.push({w[i], i});
18     long long total = 0;
19     while (pq.size() > 1) {
20         auto [wa, a] = pq.top(); pq.pop();
21         auto [wb, b] = pq.top(); pq.pop();
22         int id = w.size();                    // new internal node
23         w.push_back(wa + wb);
24         parent.push_back(-1);
25         parent[a] = parent[b] = id;
26         total += wa + wb;
27         pq.push({wa + wb, id});
28     }
29     for (int i = 0; i < n; i++) {             // code length = depth
30         int depth = 0;
31         for (int v = i; parent[v] != -1; v = parent[v]) depth++;
32         cout << ch[i] << ":" << depth << " ";
33     }
34     cout << "\ntotal bits " << total << "\n";
35     return 0;
36 }
INPUT
6
a 5
b 9
c 12
d 13
e 16
f 45
OUTPUT
a:4 b:4 c:3 d:3 e:3 f:1 
total bits 224
KEY POINT Store the tree as a parent  array: leaves are 0 … n − 1, each merge creates the next node number. Following
parents up from a leaf gives its depth, which is its code length. Check: 5·4 + 9·4 + 12·3 + 13·3 + 16·3 +
45·1 = 224.

12.3 课后习题与实验
The	Luogu	problems	for	this	chapter,	a	ladder	through	them,	and	experiments	to	try	yourself.
Key	points	to	memorise
1. Greedy = best-looking choice now, never undone; it needs a proof.
2. Exchange	argument: swap one piece of an optimal answer to match greedy, no worse.
3. Test a greedy rule against brute force on small random inputs; one mismatch kills it.
4. Coins 4, 3, 1 break "biggest coin first"; 0/1 knapsack breaks "best ratio first".
5. Splittable items: best value per weight first; compare ratios by cross-multiplying.
6. Minimise total waiting: shortest job first.
7. Most non-overlapping intervals: sort by end, take whatever fits.
8. Delete k digits for the smallest number: pop larger digits from a stack.
9. Pairs under a limit: sort, dearest with cheapest, two pointers.
10. priority_queue is a max-heap; greater<> makes a min-heap; O(log n) per operation.
11. Huffman / merge costs: repeatedly join the two smallest; total = sum of joins.
