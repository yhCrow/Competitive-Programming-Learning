2.1.3 Converting	between	types
convert.cpp
1 #include <bits/stdc++.h>
2 using namespace std;
3  
4 int main() {
5     int a = 7, b = 2;
6     cout << a / b << " " << double(a) / b << "\n";
7     double x = 3.99;
8     cout << int(x) << " " << int(-3.99) << "\n";     // cut toward 0
9     cout << int('A') << " " << char(66) << "\n";     // char <-> code
10     long long big = 1LL * 100000 * 100000;           // widen first
11     cout << big << "\n";
12     cout << round(2.5) << " " << floor(-2.5) << " " << ceil(2.1) << "\n";
13     return 0;
14 }
OUTPUT
3 3.5
3 -3
65 B
10000000000
3 -3 3
Conversion Result
double(a) / b real division (convert before dividing)
int(x) drops the fraction, toward 0
char(66) , int('A') between a character and its code
1LL * a * b multiply in long long, no overflow
round , floor , ceil nearest, down, up (return double)
TRAP double(a / b)  is still 3.0: the integer division happened first. long long x = a * b;  still overflows if
a and b are int: the product is computed as int before it is stored.

2.2.1 Input	and	output
format.cpp
1 #include <bits/stdc++.h>
2 using namespace std;
3  
4 int main() {                 // plain int here, so %d is right
5     double x = 3.14159;
6     int h = 7, m = 5, n = 42;
7     printf("%.2f\n", x);           // 2 decimals
8     printf("%02d:%02d\n", h, m);   // pad with 0 to width 2
9     printf("[%5d] [%-5d]\n", n, n); // width 5, right / left
10     cout << fixed << setprecision(3) << x << "\n";
11     cout << setw(5) << n << "|" << n << "\n";
12     cout << setfill('0') << setw(3) << n << "\n";
13     return 0;
14 }
OUTPUT
3.14
07:05
[   42] [42   ]
3.142
   42|42
042
Format Meaning
%d  / %lld int / long long
%f  / %.2f double / with 2 decimals (rounded)
%c  / %s one char / a C-string
%5d , %-5d width 5, right or left aligned
%02d width 2, padded with zeros
fixed << setprecision(k) k decimals for every later double
setw(k) width k for the next	item	only
setfill(c) padding char; stays on until changed
TRAP scanf  needs & : scanf("%d", &n) . Reading a long long  with %d  or a double  with %f  in scanf  (use
%lf ) gives garbage.

leave_home.cpp
1 #include <bits/stdc++.h>
2 using namespace std;
3  
4 int main() {
5     int s, v;                     // distance, speed (m/min)
6     cin >> s >> v;
7     int need = (s + v - 1) / v + 10;       // round up, +10 min
8     int t = ((8 * 60 - need) % 1440 + 1440) % 1440;  // wrap days

10     return 0;
11 }

KEY POINT Time problems: convert every time to minutes since midnight, compute, then convert back with / 60
and % 60 . Going back past midnight needs the % 1440 + 1440  wrap. The idea behind P1425 and P5707.

IDEA After you submit, the judge runs your program on hidden tests and gives a verdict for each. Each verdict
points to a different kind of mistake, so read it before changing code.
Verdict Meaning Usual causes
AC Accepted —
WA Wrong Answer misread rule, overflow, wrong format (spaces, newlines, decimals), missed edge case
TLE Time Limit Exceeded algorithm too slow for the limits, infinite loop, slow input/output
MLE Memory Limit Exceeded arrays far too big, endless recursion storing data
RE Runtime Error index out of range, division by 0, stack overflow from deep recursion
CE Compile Error syntax error, a function the judge's compiler lacks, wrong language chosen
Self-check	before	submitting
1. Re-read the statement and the limits; estimate the operation count.
2. Run all samples; compare the output character by character.
3. Test the smallest case (n = 1, 0, empty) and the largest values.
4. Check every product and sum for overflow; use long long .
5. Remove debug output; check spaces, newlines and decimals.
6. Compile with -Wall  and read every warning.
debug_cerr.cpp
1 #include <bits/stdc++.h>
2 using namespace std;
3  
4 int main() {
5     int n;
6     cin >> n;
7     long long sum = 0;
8     for (int i = 0; i < n; i++) {
9         int x;
10         cin >> x;
11         sum += x;
12         cerr << "i=" << i << " sum=" << sum << "\n";  // debug only
13     }
14     cout << sum << "\n";
15     return 0;
16 }
INPUT
3
1 2 3
OUTPUT
6
KEY POINT Print debug values to cerr : you see them on screen, but they are not part of the answer the judge reads
(the Output panel above shows only cout ). Still, remove them before submitting, because printing takes
time.
TRAP WA on a hidden test while the samples pass usually means an edge case or overflow. Make a tiny test
where you know the answer by hand, and compare.

Key	points	to	memorise
1. Default to long	long; write constants as 100000LL; overflow is silent.
2. A char is a number: c	-	'0', c	-	'a'	+	'A'.
3. Convert before dividing: double(a) / b; int(x) cuts toward 0.
4. printf: %lld, %.2f, %02d; cout: fixed	<<	setprecision(k), setw, setfill.
5. Times: convert to minutes; wrap with (t	%	1440	+	1440)	%	1440.
6. WA: format, overflow, edge cases. TLE: too slow or slow IO. RE: index or /0. CE: syntax.
7. Debug with cerr, remove before submitting; test n = 1 and the largest values.
