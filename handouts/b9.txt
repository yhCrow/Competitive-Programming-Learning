Tally	values	from	a	small	range,	then	print	them	in	order.
counting_sort.cpp
1 #include <bits/stdc++.h>

3

5

INPUT

2 5 2 2 5 2 2 2 1 2

IDEA When the values come from a small range (say 1 … 1000) but there are millions of them, tally them in a
counting array ( 入门 4) and print each value as many times as it was seen. O(n + range), no comparisons
at all (P1271).
TRAP Millions of numbers make input the bottleneck. With cin , turn on fast IO (fast  in your template); never
use endl  per number.

IDEA Selection	sort: for each position from the left, find the smallest value in the rest and swap it into place. It
does at most n − 1 swaps but always about n²/2 comparisons, whatever the input.
Sort Comparisons Good for
selection always ~n²/2 few swaps
bubble up to ~n²/2 counting inversions
insertion ~n to ~n²/2 nearly sorted data
quick / std::sort ~n log n everything else
4 3 2 1
3 2 1 4
2 1 3 4
1 2 3 4
start
pass 1
pass 2
pass 3
IDEA Bubble	sort: walk the array, swapping neighbours that are out
of order. After pass k the k largest values are in place at the end
(green). Each swap fixes exactly one inversion (a pair i < j with
a[i] > a[j]).
KEY POINT So the number of bubble-sort swaps = the number of inversions
= the minimum number of adjacent swaps needed to sort
(P1116). O(n²): fine for n up to a few thousand.

1 #include <bits/stdc++.h>
2 using namespace std;
3  
4 int a[10005];
5  
6 int main() {
7     int n;
8     cin >> n;
9     for (int i = 0; i < n; i++) cin >> a[i];
10     for (int i = 1; i < n; i++) {
11         int x = a[i], j = i - 1;
12         while (j >= 0 && a[j] > x) {   // shift bigger ones right

15         }
16         a[j + 1] = x;                  // drop x into the gap

KEY POINT Insertion	sort keeps a sorted prefix and slides each new value into place: fast when the data is almost
sorted. Selection	sort repeatedly picks the minimum of the rest. All three are O(n²); use them to
understand or to count, use sort  to sort.

9.3 快速排序
Partition	around	a	pivot;	k-th	smallest;	merge	sort	for	comparison.
3 7 1 5 9 2 6
pivot 5: smaller to the left, bigger to the right
3 2 1 5 9 7 6
IDEA Quicksort: pick a pivot, move smaller values
left and bigger values right (partition), then
sort the two sides the same way. On average
each level does O(n) work and there are about
log n levels.
KEY POINT To find only the k-th smallest you need just
one side after each partition: average O(n).
The standard library does this as
nth_element .
quicksort.cpp
1 #include <bits/stdc++.h>
2 using namespace std;
3  
4 int a[100005];
5  
6 void quickSort(int l, int r) {            // sorts a[l..r]
7     if (l >= r) return;
8     int pivot = a[(l + r) / 2], i = l, j = r;
9     while (i <= j) {
10         while (a[i] < pivot) i++;         // find a big one on the left
11         while (a[j] > pivot) j--;         // find a small one on the right
12         if (i <= j) { swap(a[i], a[j]); i++; j--; }
13     }
14     quickSort(l, j);                      // left part
15     quickSort(i, r);                      // right part
16 }
17  
18 int main() {
19     int n;
20     cin >> n;
21     for (int i = 0; i < n; i++) cin >> a[i];
22     quickSort(0, n - 1);
23     for (int i = 0; i < n; i++) cout << a[i] << " ";
24     cout << "\n";
25     return 0;
26 }
INPUT 1
5
4 2 4 5 1
OUTPUT 1
1 2 4 4 5
INPUT 2
6
3 3 3 3 3 3
OUTPUT 2
3 3 3 3 3 3
TRAP Taking the first element as pivot makes already-sorted data O(n²). The middle element (or a random one)
avoids that. Contest template problems (P1177) include such data on purpose; in practice just call sort .

merge_inversions.cpp
1 #include <bits/stdc++.h>
2 using namespace std;
3  
4 int a[100005], tmp[100005];
5 long long inv = 0;
6  
7 void mergeSort(int l, int r) {            // sorts a[l..r]
8     if (l >= r) return;
9     int m = (l + r) / 2;
10     mergeSort(l, m);
11     mergeSort(m + 1, r);
12     int i = l, j = m + 1, k = l;
13     while (i <= m && j <= r) {
14         if (a[i] <= a[j]) tmp[k++] = a[i++];
15         else { tmp[k++] = a[j++]; inv += m - i + 1; }  // a[i..m] > a[j]
16     }
17     while (i <= m) tmp[k++] = a[i++];
18     while (j <= r) tmp[k++] = a[j++];
19     for (int t = l; t <= r; t++) a[t] = tmp[t];
20 }
21  
22 int main() {
23     int n;
24     cin >> n;
25     for (int i = 0; i < n; i++) cin >> a[i];
26     mergeSort(0, n - 1);
27     cout << inv << "\n";
28     for (int i = 0; i < n; i++) cout << a[i] << " ";
29     cout << "\n";
30     return 0;
31 }

4 3 2 1
OUTPUT 1
6
1 2 3 4
INPUT 2
5
2 4 1 3 5
OUTPUT 2

1 2 3 4 5
KEY POINT Merge	sort sorts each half, then merges two sorted lists by repeatedly taking the smaller front value:
always O(n log n). While merging, taking from the right half jumps over all values left in the left half,
which counts inversions in O(n log n) instead of bubble sort's O(n²).

IDEA sort(a, a + n)  puts a[0] … a[n-1]  in increasing
order in O(n log n). After sorting, equal values sit next
to each other, the smallest is at the front, and the k-th
smallest is at index k − 1.
KEY POINT The range is half-open: first element included, end
pointer excluded. For a 1-based array use sort(a + 1,
a + n + 1) .

9.4.3 Sorting	records	by	several	keys
Main	key	first;	each	tie-break	only	when	everything	before	it	is	equal.
scholarship.cpp
1 #include <bits/stdc++.h>
2 using namespace std;
3  
4 struct Stu {
5     int id, chinese, math, english, total;
6 };
7  
8 bool cmp(const Stu &x, const Stu &y) {
9     if (x.total != y.total) return x.total > y.total;        // 1. total high
10     if (x.chinese != y.chinese) return x.chinese > y.chinese; // 2. Chinese high
11     return x.id < y.id;                                      // 3. id small
12 }

21         cin >> s[i].chinese >> s[i].math >> s[i].english;
22         s[i].total = s[i].chinese + s[i].math + s[i].english;
23     }
24     sort(s, s + n, cmp);

IDEA Write the comparator as a ladder: compare
key 1; if different, return that comparison.
Otherwise move to key 2, and so on. The
last rung is usually the input order (an id
you stored), which makes every order
fully defined (P1093, P1068, P1786).
KEY POINT Need "same keys keep input order"?
Either add the id as the last key, or call
stable_sort , which never reorders
equal elements (P1104: same birthday,
later input first → id descending as the
last key).
TRAP A comparator must be a strict order:
cmp(x, x)  must be false. Using >=  or
<=  breaks sort , sometimes with a crash.
KEY POINT Cut-off lines: sort, take the score of the
person at position ⌊m × 1.5⌋, then count
everyone with score ≥ that line, because
ties at the line all pass (P1068).

9.5 课后习题与实验
The	Luogu	problems	for	this	chapter,	a	ladder	through	them,	and	experiments	to	try	yourself.
Key	points	to	memorise
1. sort(a,	a	+	n) is O(n log n); 1-based: sort(a	+	1,	a	+	n	+	1); decreasing: greater<int>().
2. After sorting: duplicates are adjacent, k-th smallest is at index k − 1.
3. Bubble-sort swaps = inversions = fewest adjacent swaps; O(n²).
4. Insertion sort is fast on nearly sorted data; still O(n²) in general.
5. Small value range: counting	sort, O(n + range).
6. Quicksort: partition around a pivot; use the middle or a random pivot.
7. nth_element(a,	a	+	k,	a	+	n): k-th smallest in average O(n).
8. Merge sort is always O(n log n) and counts inversions while merging.
9. Remove duplicates: sort, then v.erase(unique(…),	v.end()).
10. Multi-key comparator: a ladder of "if different, return"; finish with the id.
11. Comparator must be strict: never >=; stable_sort keeps equal items in input order.
12. Compare huge numbers as strings: length first, then dictionary order.
13. Millions of inputs: fast IO on, no endl.
14. (C) qsort uses a comparator returning negative / zero / positive.
