11.1 最小割树
Gusfield:	n	−	1	flows;	min	edge	on	the	tree	path.
IDEA A Gomory–Hu	tree ( 最小割树 ) of an undirected weighted graph is a tree on the same vertices such that,
for every pair u, v, the minimum u–v cut in the graph equals the smallest	edge on the tree path u–v. It
needs only n − 1 max-flow runs and then answers all n² min-cut queries.
KEY POINT Gusfield's simple construction: parent[i] = 1 for all i. For i = 2 … n: compute the min cut between i and
parent[i] (weight w, side S containing i); set the tree edge (i, parent[i], w); for every j > i with parent[j] =
parent[i] and j ∈ S, set parent[j] = i. No graph contraction needed (P4897).
竞 赛 拓 展 专 题  · NOI 篇  · NOI 专 题
All-pairs min cuts from n − 1 flows, the tree of blocks that tells which vertices every path must use,
reachable totals by shortest paths on residues, and easy colouring on chordal graphs.

16     fill(level, level + n + 1, -1); queue<int> q; level[s] = 0; q.push(s);
17     while (!q.empty()) { int u = q.front(); q.pop(); for (int k = 0; k < int(g[u].size()); k++) { Edge 
&x = e[g[u][k]]; if (x.cap > 0 && level[x.to] < 0) { level[x.to] = level[u] + 1; q.push(x.to); } } }
18     return level[t] >= 0;

20 long long dfs(int u, int t, long long f) {
21     if (u == t) return f;
22     for (int &k = it[u]; k < int(g[u].size()); k++) {
23         int id = g[u][k]; Edge &x = e[id];
24         if (x.cap > 0 && level[x.to] == level[u] + 1) { long long got = dfs(x.to, t, min(f, x.cap)); if 
(got) { x.cap -= got; e[id ^ 1].cap += got; return got; } }
25     }
26     return 0;

30     long long r = 0;
31     while (bfs(s, t)) { fill(it, it + n + 1, 0); while (long long f = dfs(s, t, LLONG_MAX)) r += f; }

33 }

11.2 圆方树
Square	node	per	block;	round	nodes	on	the	path.
IDEA The block-cut	tree ( 圆方树 ): for every vertex-biconnected block ( 进阶篇  第 12 章 ) create a "square" node
and connect it to the "round" nodes (original vertices) of the block. The result is a tree. Every simple path
u–v in the graph uses exactly the blocks on the tree path between u and v, and the vertices that every u–v
path must pass are the round nodes on that tree path.
KEY POINT So "how many vertices lie on all u–v paths" ( 道路相遇  P4320) = number of round nodes on the tree path =
(path length in nodes + 1) / 2. Build it with the same Tarjan stack as vertex_bcc.cpp, creating a square node
per popped block.

1 #include <bits/stdc++.h>
2 using namespace std;

4 const int N = 200005;
5 int n, m, dfn[N], low[N], timer_ = 0, sq;
6 vector<int> g[N], t[2 * N], stk;
7 int dep[2 * N], up[2 * N][19];
8  
9 void tarjan(int u) {
10     dfn[u] = low[u] = ++timer_; stk.push_back(u);
11     for (int k = 0; k < int(g[u].size()); k++) {
12         int v = g[u][k];
13         if (!dfn[v]) {
14             tarjan(v);
15             low[u] = min(low[u], low[v]);
16             if (low[v] >= dfn[u]) {                 // a block: new square node
17                 ++sq;
18                 while (true) { int x = stk.back(); stk.pop_back(); t[sq].push_back(x); 
t[x].push_back(sq); if (x == v) break; }
19                 t[sq].push_back(u); t[u].push_back(sq);
20             }
21         } else low[u] = min(low[u], dfn[v]);
22     }
23 }
24 void dfs(int u, int p) {
25     up[u][0] = p;
26     for (int k = 1; k < 19; k++) up[u][k] = up[up[u][k - 1]][k - 1];
27     for (int i = 0; i < int(t[u].size()); i++) { int v = t[u][i]; if (v != p) { dep[v] = dep[u] + 1; 
dfs(v, u); } }
28 }
29 int lca(int a, int b) {
30     if (dep[a] < dep[b]) swap(a, b);
31     for (int k = 18; k >= 0; k--) if (dep[a] - (1 << k) >= dep[b]) a = up[a][k];
32     if (a == b) return a;
33     for (int k = 18; k >= 0; k--) if (up[a][k] != up[b][k]) { a = up[a][k]; b = up[b][k]; }
34     return up[a][0];
35 }

11.3 同余最短路
Residues	mod	the	smallest	step;	count	reachable	totals.
IDEA Shortest	paths	modulo	a	number ( 同余最短路 ): which totals can be written as ax + by + cz with x, y, z
≥ 0? Work modulo a (the smallest step): for each residue r mod a, let d[r] = the smallest reachable total ≡
r. Then every d[r] + k·a is reachable too. The d[r] are shortest paths on a graph of a vertices: r → (r + b)
mod a with weight b, r → (r + c) mod a with weight c.
KEY POINT Count reachable totals ≤ h: Σr (⌊(h − d[r]) / a⌋ + 1) over residues with d[r] ≤ h. Graph size a, not h, so h can
be 2⁶³ ( 跳楼机  P3403: floors reachable from floor 1).

3  
4 typedef long long ll;
5 int main() {
6     ll h, x, y, z;
7     cin >> h >> x >> y >> z;
8     h -= 1;                                        // start at floor 1: count totals 0..h-1
9     vector<ll> d(x, LLONG_MAX);
10     d[0] = 0;
11     priority_queue<pair<ll, int>, vector<pair<ll, int>>, greater<pair<ll, int>>> pq;
12     pq.push(make_pair(0LL, 0));
13     while (!pq.empty()) {
14         ll dd = pq.top().first; int r = pq.top().second; pq.pop();
15         if (dd > d[r]) continue;
16         ll step[2] = {y, z};
17         for (int k = 0; k < 2; k++) {
18             int nr = (r + step[k]) % x;
19             if (dd + step[k] < d[nr]) { d[nr] = dd + step[k]; pq.push(make_pair(d[nr], nr)); }
20         }
21     }
22     ll ans = 0;
23     for (int r = 0; r < x; r++) if (d[r] <= h) ans += (h - d[r]) / x + 1;
24     cout << ans << "\n";
25     return 0;
26 }

11.4 弦图、平面图与 	HLPP
MCS	ordering;	planar	duality;	preflow	push.
IDEA A graph is chordal ( 弦图 ) if every cycle of length ≥ 4 has a chord. Equivalently it has a perfect
elimination	ordering: an order where each vertex's later neighbours form a clique. Maximum
cardinality	search (MCS): repeatedly number the unnumbered vertex with the most numbered
neighbours; reversing that order gives a perfect elimination ordering exactly when the graph is chordal.
O(n + m).
KEY POINT On chordal graphs many hard problems become easy: the chromatic number equals the maximum clique,
which is max over v of (1 + number of earlier-numbered neighbours in MCS order); greedy colouring along
the perfect elimination order achieves it ( 神奇的国度  P3196).

6     cin >> n >> m;
7     vector<vector<int>> g(n + 1);
8     for (int i = 0; i < m; i++) { int u, v; cin >> u >> v; g[u].push_back(v); g[v].push_back(u); }

12     int top = 0, ans = 0;
13     for (int step = 0; step < n; step++) {
14         int v = -1;
15         while (v < 0) {                            // vertex with the largest label (lazy buckets)
16             while (bucket[top].empty()) top--;
17             int c = bucket[top].back(); bucket[top].pop_back();
18             if (!done[c] && label[c] == top) v = c;
19         }
20         done[v] = 1;
21         ans = max(ans, label[v] + 1);              // label = earlier neighbours = clique with v
22         for (int k = 0; k < int(g[v].size()); k++) {
23             int u = g[v][k];
24             if (!done[u]) { label[u]++; bucket[label[u]].push_back(u); top = max(top, label[u]); }
25         }
26     }

IDEA k-th	shortest	path (k 短路 , walks may repeat vertices): run Dijkstra from t on the reversed graph to get
h(v) = dist(v, t), an exact heuristic. Then run A* from s with key g + h(v): the i-th time t is popped, g is the
i-th shortest path length. Each vertex needs to be expanded at most k times.
KEY POINT A* is O(k · m log) in the worst case and is what most solutions use. The guaranteed method builds the
shortest-path tree to t; every path is the tree path plus a list of "side-track" edges with cost w + h(v) − h(u),
kept in persistent	leftist	heaps ( 第 5 章 ), giving O((n + m) log m + k log k) (P2483).

2 using namespace std;
3  
4 typedef long long ll;
5 typedef pair<ll, int> pli;
6 const ll INF = LLONG_MAX / 4;
7  
8 int main() {
9     int n, m, k;
10     cin >> n >> m >> k;
11     vector<vector<pair<int, ll>>> g(n + 1), rg(n + 1);
12     for (int i = 0; i < m; i++) { int u, v; ll w; cin >> u >> v >> w; g[u].push_back({v, w}); 
rg[v].push_back({u, w}); }
13     int s = 1, t = n;
14     vector<ll> h(n + 1, INF);                          // h(v) = dist(v, t)
15     priority_queue<pli, vector<pli>, greater<pli>> pq;
16     h[t] = 0; pq.push({0, t});
17     while (!pq.empty()) {
18         pli c = pq.top(); pq.pop();
19         if (c.first > h[c.second]) continue;
20         for (int i = 0; i < int(rg[c.second].size()); i++) {
21             int v = rg[c.second][i].first; ll w = rg[c.second][i].second;
22             if (h[c.second] + w < h[v]) { h[v] = h[c.second] + w; pq.push({h[v], v}); }
23         }
24     }
25     vector<int> cnt(n + 1, 0);
26     vector<ll> ans;
27     priority_queue<pair<ll, pair<ll, int>>, vector<pair<ll, pair<ll, int>>>, greater<pair<ll, pair<ll, 
int>>>> q;   // (g + h, (g, v))
28     if (h[s] < INF) q.push({h[s], {0, s}});
29     while (!q.empty() && int(ans.size()) < k) {

36         }
37     }

11.6 全局最小割与 	Borůvka
Stoer–Wagner	phases;	cheapest	edge	per	component.
IDEA Stoer–Wagner ( 全局最小割 ): the minimum cut over all ways to split an undirected graph into two
nonempty parts, with no fixed source or sink. One phase grows a set A by repeatedly adding the vertex
most tightly connected to A; the last two added, s and t, satisfy: the weight of t to the rest is the minimum
s–t cut. Record it, merge s and t, repeat n − 1 times.
KEY POINT O(n³) with an adjacency matrix (O(nm + n² log n) with a heap). It beats running max flow n − 1 times, and
the code is shorter (P5632).

KEY POINT Checked against trying all 2ⁿ − 2 splits in Python.
IDEA Borůvka: in each round, every component picks its cheapest outgoing edge, and all picked edges are
added at once. Each round at least halves the number of components, so there are O(log n) rounds. Break
ties by edge index so that the picked edges never form a cycle.
KEY POINT Its power is that a round only needs "the cheapest edge leaving each component", which can be found
without	listing	the	edges: on a complete graph with weight ai xor aj use a trie (CF888G Xor-MST), on
points use geometry. That gives MSTs of graphs with n² implicit edges in O(n log² n).

11.7 平面图欧拉公式
V	−	E	+	F	=	1	+	C;	E	≤	3V	−	6.
IDEA Euler's	formula	for	planar	graphs ( 平面图欧拉公式 ): a connected planar graph drawn without
crossings has V	−	E	+	F	=	2 (F counts the outer face). With C connected components: V − E + F = 1 + C.
Consequences: a simple planar graph with V ≥ 3 has E ≤ 3V − 6 (and E ≤ 2V − 4 without triangles), so it is
sparse, and its average degree is below 6.
KEY POINT Typical uses: count the regions cut out by segments or chords (build the planar graph: intersections
become vertices, then F = E − V + C + 1), prove that a graph is not planar (K5: E = 10 > 9), and bound edge
counts so O(E) algorithms on planar graphs are O(V). With the dual graph ( 第 4 节 ) it turns planar
minimum cuts into shortest paths.
Example V E F = E − V + C + 1
n points on a circle, all chords, no three meet n + C(n, 4) n + 2·C(n, 4) + C(n, 2) 1 + C(n, 2) + C(n, 4)
triangle with all medians 7 12 7 (6 inside + outer)
tree with n vertices n n − 1 1

Key	points	to	memorise
1. Gomory–Hu: n − 1 max flows; u–v min cut = min edge on the tree path.
2. Gusfield: parent = 1; cut (i, parent[i]); later j on i's side with same parent ⇒ parent[j] = i.
3. Block-cut tree: square node per block; must-pass vertices = round nodes on the path.
4. 同余最短路 : d[r] smallest total ≡ r (mod a); count Σ (h − d[r]) / a + 1.
5. Chordal: MCS order; χ = max clique = max (label + 1).
6. Planar min cut = shortest path in the dual.
7. k 短路 : h = dist to t (reverse Dijkstra); A* on g + h; i-th pop of t = i-th path.
8. Stoer–Wagner: add most-connected vertex; last one's weight = s–t cut; merge s, t.
9. Borůvka: every component takes its cheapest edge; O(log n) rounds; implicit edges.
10. Euler: V − E + F = 1 + C; simple planar ⇒ E ≤ 3V − 6.
